# Auth & User API Reference

For installing and running the project, see [`getting ready.md`](getting%20ready.md). This document is a reference for how authentication and the user API actually work in the code.

---

## Architecture Overview

```
Browser
  │
  ▼
nginx :8443 (HTTPS)        ← single entry point
  ├── /api/*       →  NestJS backend :3001 (nginx strips the /api/ prefix)
  ├── /socket.io/*  →  NestJS backend :3001 (websockets)
  └── /*           →  Next.js frontend :3000

NestJS backend (no global prefix set in main.ts)
  ├── AuthController   → /auth/*
  └── UsersController  → /users/*
        └── Prisma → PostgreSQL
```

The backend itself has no `/api` prefix — nginx's `/api/` location proxies to the backend root and strips the matched prefix. So a request the browser sends to `/api/auth/login` reaches the backend as `/auth/login`. All paths in this document are shown as the **browser** sees them (with `/api`).

There are no auth cookies: the backend returns `accessToken`/`refreshToken` in the JSON response body, and the frontend sends the access token back as an `Authorization: Bearer <token>` header. Refresh tokens are sent in the request body, not a header or cookie.

Avatars are stored as compressed base64 data URLs directly in the `User.avatar` column — no disk storage, no S3.

## Environment Variables (auth-related)

Set in `.env` (see `.env.example`; generated by `make jwt-secrets`, see [`getting ready.md`](getting%20ready.md)).

| Variable | Used for |
|---|---|
| `JWT_SECRET` | Signs/verifies access tokens (15 min, hardcoded in `AuthService`) |
| `JWT_REFRESH_SECRET` | Signs/verifies refresh tokens (7 days, hardcoded in `AuthService`) |
| `JWT_RESET_SECRET` | Signs/verifies password-reset tokens (30 min) |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | Google OAuth app credentials |
| `GOOGLE_CALLBACK_URL` | Must exactly match the redirect URI registered in Google Cloud Console, e.g. `https://<domain>/api/auth/google/callback` |
| `FRONTEND_URL` | Where the backend redirects after Google login and where password-reset emails point; falls back to `https://transcendance.rmanzanas.com` if unset |
| `RESEND_API_KEY` | Used by `MailService` (`backend/src/auth/mail.service.ts`) to send password-reset emails via [Resend](https://resend.com) |

Note: `JWT_SECRET`/`JWT_REFRESH_SECRET`/`JWT_RESET_SECRET` are generated by `make jwt-secrets` (`openssl rand -hex 32`). There is no `JWT_EXPIRES_IN`/`JWT_REFRESH_EXPIRES_IN` override in effect today — token lifetimes (15m / 7d / 30m) are hardcoded in `AuthService`.

## Auth Endpoints

Paths as seen by the browser (nginx strips `/api/` before forwarding to the backend).

### Register
```
POST /api/auth/register
Content-Type: application/json

{ "email": "user@example.com", "username": "myname", "password": "mypassword" }
```
- `username`: 3–20 chars, letters/numbers/underscores only.
- `password`: 8–72 chars (bcrypt silently truncates beyond 72 bytes).
- Returns `{ accessToken, refreshToken }` (registers, then logs in).

### Login
```
POST /api/auth/login
Content-Type: application/json

{ "email": "user@example.com", "password": "mypassword" }
```
Validated by `LocalStrategy`/`LocalAuthGuard`. Returns `{ accessToken, refreshToken }`.

### Refresh tokens
```
POST /api/auth/refresh
Content-Type: application/json

{ "refreshToken": "<refreshToken>" }
```
Note the field is `refreshToken`, extracted from the request body by `JwtRefreshStrategy`. Verified against the bcrypt hash stored on the user. Returns `{ accessToken, refreshToken }` — both rotate on every refresh.

### Logout
```
POST /api/auth/logout
Authorization: Bearer <accessToken>
```
Clears the stored refresh-token hash from the DB. Returns `{ "message": "Logged out" }`.

### Forgot password
```
POST /api/auth/forgot-password
Content-Type: application/json

{ "email": "user@example.com", "lang": "en" }
```
- `lang` is optional (`en`, `es`, or `lv` templates in `MailService`; defaults to `en`).
- Always returns the same `{ "message": "If that email exists, a reset link has been sent" }`, regardless of whether the email exists or belongs to a Google-only account — this is deliberate, to avoid leaking account existence.
- If the account exists and has a local password, a reset email is sent via Resend with a link to `${FRONTEND_URL}/reset-password?token=<jwt>`. The token is signed with `JWT_RESET_SECRET` and expires in 30 minutes.

### Reset password
```
POST /api/auth/reset-password
Content-Type: application/json

{ "token": "<token from the email link>", "newPassword": "newpassword" }
```
- `newPassword`: 8–72 chars.
- Returns `{ "message": "Password updated" }`, or `401` with `{ code: "RESET_TOKEN_INVALID" }` if the token is invalid, expired, or not a password-reset token.

### Google OAuth
```
GET /api/auth/google
```
Redirects to Google's consent screen (scopes: `email`, `profile`). After approval, Google redirects to:
```
GET /api/auth/google/callback
```
The backend finds or creates a user by email (new users get `password: null`, `authProvider: GOOGLE`, and a username auto-derived from the email local part, de-duplicated with a numeric suffix if taken), issues tokens, then redirects the browser to:
```
<FRONTEND_URL>/auth/callback?accessToken=...&refreshToken=...
```
The frontend's `/auth/callback` page reads those query params, stores the tokens, and redirects to `/`.

## User Endpoints

All routes below require `Authorization: Bearer <accessToken>` (`JwtAuthGuard`).

### Get current user
```
GET /api/users/me
```
Returns a sanitized user object (no `password` or `refreshToken`):
```json
{
  "id": "uuid",
  "email": "user@example.com",
  "username": "myname",
  "avatarPath": "data:image/jpeg;base64,..." ,
  "hasPassword": true,
  "createdAt": "2026-06-25T..."
}
```
`avatarPath` is either the stored base64 data URL or, if the user has no custom avatar, a generated DiceBear placeholder URL. `hasPassword` is `false` for Google OAuth accounts that never set a local password.

### Update profile
```
PUT /api/users/me
Content-Type: application/json
Authorization: Bearer <accessToken>

{
  "username": "newname",          // optional, 3–20 chars, letters/numbers/underscores
  "currentPassword": "oldpass",   // required only when setting newPassword, min 8 chars
  "newPassword": "newpass"        // optional, min 8 chars
}
```
- Changing the password requires `currentPassword` and fails for accounts with no local password (Google OAuth) with `400 OAUTH_PASSWORD_CHANGE_FORBIDDEN`.
- A taken username returns `409 USERNAME_IN_USE`.

### Upload avatar
```
POST /api/users/me/avatar
Content-Type: application/json
Authorization: Bearer <accessToken>

{ "avatar": "data:image/jpeg;base64,..." }
```
- The frontend (`EditProfileModal.tsx`) compresses the image client-side with `browser-image-compression` (`maxSizeMB: 0.8`, `maxWidthOrHeight: 256`) before encoding it as a data URL.
- The backend rejects anything not starting with `data:image/`, and rejects strings longer than 1,100,000 characters (`400 Invalid image data` / `400 Image too large`).

### Get stats / leaderboard / another user
```
GET /api/users/me/stats
GET /api/users/leaderboard[?scope=friends]
GET /api/users/:id
```
Not auth-specific, but also behind `JwtAuthGuard`; `GET /api/users/:id` returns the same sanitized shape as `/users/me`.

## Frontend Auth

### Token storage
Tokens are stored in `localStorage` via `frontend/app/lib/auth.ts`. Keys: `access_token`, `refresh_token`.

### Authenticated fetch
`apiFetch` in `frontend/app/lib/api.ts` prefixes calls with `/api`, attaches the Bearer token, and retries once on `401` (calls `/auth/refresh`, stores the new tokens, retries). If the refresh also fails, it clears tokens and redirects to `/login`.

```ts
import { apiFetch } from '@/app/lib/api';

const res = await apiFetch('/users/me');
const user = await res.json();
```

`AuthContext` also proactively refreshes the tokens every 12 minutes while a user is logged in (`frontend/context/AuthContext.tsx`), ahead of the 15-minute access-token expiry.

### Auth context
`useAuth()` from `frontend/context/AuthContext.tsx` gives any component:

```ts
const { user, loading, login, logout, refetchUser } = useAuth();
```

- `user` — sanitized user object, or `null` if not logged in.
- `loading` — `true` while the initial `/users/me` check is in flight.
- `login(accessToken, refreshToken)` — stores tokens, fetches the user, updates state.
- `logout()` — clears tokens, resets user to `null` (does not call `/auth/logout` on the backend).
- `refetchUser()` — re-fetches `/users/me` and updates state (call after profile edits).

### Protecting a page
There is no shared `ProtectedRoute`/HOC — each page that needs auth repeats this pattern inline (see e.g. `app/page.tsx`, `app/profile/page.tsx`, `app/game/page.tsx`, `app/chat/page.tsx`, `app/friends/page.tsx`):

```tsx
const { user, loading } = useAuth();
const router = useRouter();

useEffect(() => {
  if (!loading && !user) router.replace('/login');
}, [loading, user, router]);

if (loading || !user) return null; // or a loading state
```

## Database Schema (auth-relevant fields)

From `backend/prisma/schema.prisma`:

```prisma
enum AuthProvider {
  LOCAL
  GOOGLE
}

model User {
  id           String       @id @default(uuid())
  email        String       @unique
  username     String       @unique
  password     String?      // bcrypt hash; null for OAuth-only users
  avatar       String?      // base64 data URL, or null (frontend falls back to a generated avatar)
  refreshToken String?      // bcrypt hash of the current refresh token
  createdAt    DateTime     @default(now())
  authProvider AuthProvider @default(LOCAL)
  providerId   String?      @unique   // Google profile id, for GOOGLE accounts
}
```

Schema changes and migrations are covered in [`getting ready.md`](getting%20ready.md) (`make install-deps` runs `prisma migrate deploy`).

## Common Issues

**`password authentication failed for user "postgres"`**  
Duplicate `DATABASE_URL` or `DB_PASSWORD` in `.env`. Each key must appear exactly once, and the password must match what the Postgres volume was initialized with. If in doubt: `docker compose down -v` and start fresh.

**`413 Payload Too Large` on avatar upload**  
nginx's config sets `client_max_body_size 5m` and the backend's `express.json()` limit is `5mb`. If you still see this, check both are in effect and restart `nginx`/`backend`.

**Google OAuth `redirect_uri_mismatch`**  
The URI registered in Google Cloud Console must exactly match `GOOGLE_CALLBACK_URL` in `.env`, including scheme (`http` vs `https`) and port.

**Password reset email never arrives**  
`forgot-password` always returns success even when nothing was sent — this is intentional. Check `RESEND_API_KEY` is set and, if sending to an address other than the Resend account's own, that a sending domain is verified in Resend (see [`getting ready.md`](getting%20ready.md), step 3.6).

**`401` right after logging in with a fresh refresh token**  
The refresh endpoint expects the field name `refreshToken` in the JSON body, not `refresh_token`.
